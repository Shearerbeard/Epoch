B & C at Runtime

The two surfaces from the skeletons document, drawn as control flow: what would actually run, where the loops close, and where each design pays its consistency bill. Both surfaces are proposed, not shipped; see the ADRs. Companion to the failure atlas and the type skeletons.

Panel B · saga + event feed

B — the at-least-once loop

Panel C · atomic multi-stream batch

C — one commit, no window

Reading the two charts together B has two authors (Epoch machinery + consumer react/execute) and buys integration; its loop closes over time. C has one author (the consumer's batch) and buys invariants; its loop closes inside one transaction. The draw wants C. Everything that reacts to a draw wants B.
